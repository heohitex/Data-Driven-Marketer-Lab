# 🎯 Clickstream Log Sequencing & Data-Driven Landing Page Optimization (Cross-functional Launch)

본 프로젝트는 공식 홈페이지의 원천 웹 로그(Clickstream) 데이터를 시퀀싱하여 **유저 퍼널의 병목을 진단하고, 도출된 가설을 바탕으로 타깃 페르소나 맞춤형 신규 라이브 랜딩페이지 개편 기획 및 최종 크로스 기능적(Cross-functional) 협업 배포를 주도한 데이터 기반 프로덕트 그로스(Growth) 프로젝트**입니다.

정형화된 서드파티 툴의 한계를 넘어 원천 클릭스트림 로그 분석 결과 도출된 **"가격 선진입 유저의 높은 이탈률(2.5배)"** 리스크를 해결하기 위해, 단순 가격 할인 소구 위주의 As-Is 레이아웃을 탈피하고 **"1인 기업의 생존과 성장"이라는 본질적 가치와 공신력 있는 비용 절감 데이터**를 매핑한 To-Be 프로덕트 라인을 성공적으로 런칭했습니다.

---

## 🚀 Key Business Challenges

* **상품 카테고리별 전환 퍼널 차이 규명**: 시간패스, 1일권, 주말&야간패스, 무제한패스 등 상품 성격에 따른 첫 구매 유저의 필수 거점 페이지와 숙려 기간(`convDuration`) 분석.
* **미구매 이탈 유저의 '데드엔드(Dead-end)' 포착**: 전환 허들을 넘지 못하고 탈락하는 잠재 유저들이 최종적으로 머무는 변곡점을 복원하여 UI/UX 리디자인 근거 마련.
* **데이터 인사이트 기반의 가치 제안(Value Proposition) 설계**: 거대한 할인율 소구(As-Is)에서 발생하는 시각적 피로도와 높은 초반 탈락률을 방어하기 위한 페르소나 중심 논리 기획.
* **크로스 기능적 협업을 통한 전사 이니셔티브 주도**: 정량적 데이터 지표를 근거로 대안 기획안을 수립하여 디자이너·퍼블리셔와 매끄럽게 커뮤니케이션하고 실 프로덕트 라이브 배포 완수.

## 🏗️ Clickstream Processing & CRO Action Loop

```text
[AWS RDS Production DB] ──(SSH Tunnel Forwarder)──► [Python Preprocessing Engine]
                                                             │
 노이즈 정제 (MainActivity, UIViewController 백아웃) ◀───────┘
 세션 시퀀싱 (groupby 기반 유저별 이동 순번 page_row_num 복원)
                                                             │
                                                             ▼
 [Data Insight: 가격 선진입 시 이탈률 2.5배]
                                                             │
                                                             ▼
 [Action: 페르소나 중심 랜딩페이지 가치 제안 기획]
 (할인율 중심 소구 탈피 -> 본질 가치 및 공신력 있는 비용 데이터 매핑)
                                                             │
                                                             ▼
 [Cross-functional Collaboration] ─────────────► [Final Live Deployment 🎉]
 (디자이너 / 퍼블리셔 협업을 통한 라이브 런칭)
```

## 🛠️ Data Engineering & Pipeline Core Logics

### 1. 캠페인 캘린더 타임라인 익명화 (Promotion Timeline Masking)
실제 진행된 전사 프로모션 타임라인 스케줄과 일별 모객 볼륨 트렌드를 결합하여 프로모션 기여 효과를 정밀하게 검증하기 위해, 일별 날짜 범위를 인식하여 전용 캠페인 코드로 자동 치환하는 분기 매핑 함수(`get_promotion_name`)를 구현했습니다. 사내 대외비 항목 보호를 위해 실제 프로모션 명칭은 글로벌 표준 기술 플레이스홀더(`PROMOTION_TYPE_ALPHA` 등)로 익명화 처리되었습니다.

### 2. 노이즈 데이터 백아웃 및 유효 웹 로그 필터링 (Noise Cleaning)
앱 내 가상 뷰 컨트롤러나 회계 처리 단계에서 중복 발생하는 계정 가입/인증 페이지 및 디바이스 기본 액티비티 요소를 정규표현식 매칭 기법으로 과감히 백아웃 처리하여, 유저의 순수한 '콘텐츠 및 상품 탐색' 로그만 보존했습니다.

### 3. 파이썬 기반 유저 세션 시퀀싱 알고리즘 (Clickstream Sequencing)
동일 유저의 불규칙한 이동 시계열 데이터를 보정하기 위해 `sort_values(['user_id_2', 'event_timestamp'])` 처리 후, 유저 세그먼트 내에서 유니크하게 페이지가 전환되는 지점만을 추적하여 이동 순번(`page_row_num`)과 조회 페이지 깊이(`row_num_page`)를 윈도우 함수 형태로 동적 할당했습니다.

## 💡 Key Analytical Insights & Cross-functional CRO Action

### 1. 데이터 분석 결과 및 문제 진단 (As-Is)
* **가격 직진형 소구의 한계**: 최초 진입 시점(`page_row_num == 1`)에 단순 가격표나 할인 쿠폰 탭으로 랜딩된 유저는 초기 이탈률이 공간 특장점을 먼저 본 유저 대비 **약 2.5배** 높게 나타났습니다.
* **체리피커 가중 현상**: 할인 프로모션 스케줄 매핑 결과, 모객 볼륨은 평시 대비 2.2배 급증했으나 유저들의 페이지 탐색 깊이(`row_num_page`)가 낮아 단발성 체류 후 이탈하는 보틀넥이 확인되었습니다. 가격 소구를 최상단에 배치하는 기존 레이아웃(As-Is)의 근본적 체질 개선이 요구되었습니다.

### 2. 데이터 기반 크로스 기능적 랜딩페이지 최적화 배포 (To-Be)
분석 결과를 기반으로 **"가격 소구 위주에서 페르소나 가치 및 비용 절감 논리 소구"**로 패러다임을 전환하는 전략적 기획안을 수립하고, 타 부서와의 긴밀한 데이터 공유를 통해 신규 라이브 랜딩페이지를 협업 배포했습니다.

#### 🔄 As-Is vs To-Be 데이터 기반 리디자인 매트릭스
| 기존 방식 (As-Is 블록) | **데이터 기반 개편 (To-Be 블록)** | 크리에이티브 반영 및 협업 로직 |
| :--- | :--- | :--- |
| **가격 및 할인 직진형 레이아웃**<br>`"월 10만원대부터!", "최저가 보장 위크"`<br>→ 가격 필터링으로 인한 초반 이탈 유도 | **페르소나 중심 공감형 헤드라인**<br>`"1인 대표를 위한 멤버십 추천 - 파이브스팟"`<br>→ 핵심 타깃 목적성 일치로 이탈 방지 | 최상단 초반 진입 섹션에서 가격 저항을 지우고, 1인 기업이 공간을 필요로 하는 근본적 유즈케이스와 공감대 형성 |
| **단순 매체 나열 및 텍스트 안내**<br>→ 인프라 탐색 깊이 저하 및 체류 시간 감소 보틀넥 발생 | **공신력 있는 데이터 기반 비용 비교**<br>`강남 1인 사무실 임대 비용(NOC) 대비 파이브스팟 연간 절약 비용 지표 시각화` | 한국부동산원 임대동향조사 공신력 데이터 매핑. 명확한 절약 수치 제시로 **페이지 체류 시간 및 논리적 설득력 강화** |
| **쿠폰 다운로드 및 복잡한 정산 유도**<br>→ 결제 직전 심리적 저항 유발 | **핵심 심리적 장벽 선제거 (Friction 제거)**<br>`"보증금 눈치에서 벗어났습니다. 0원"` | 초기 비용에 부담을 느끼는 1인 대표 페르소나의 장벽인 보증금/관리비를 '0원'으로 제안하는 크리에이티브 전략을 도출, **최종 전환율(CVR) 상승 유도** |

## 📈 Post-Launch CRO Roadmap (추후 최적화 실험 계획)

단발성 배포에 그치지 않고 배포 이후 데이터 누적 볼륨에 따라 신속하고 결함 없는 메시지 최적화(CRO) 실험을 전개하기 위해, 기획 단계에서부터 랜딩페이지 구조를 **가변 영역(Variable Blocks)**과 **고정 영역(Constant Blocks)**으로 디커플링하여 데이터 거버넌스를 확보했습니다.

![A/B Testing Framework](./06-web-funnel-conversion-analysis/ab-testing-framework.png)

* **Variable Blocks (1~2번 섹션) - 실험 영역**:
  * 초기 진입 유저의 첫 이탈을 방어하고 설득 논리를 극대화하기 위해 향후 카피라이팅 및 비용 비교 인터랙션 방식을 바꾼 베리에이션(2안, 3안, 4안)을 순차적으로 교체 배치할 실험 파이프라인 영역입니다.
* **Constant Blocks (3~6번 섹션) - 통제 영역**:
  * 실제 제공되는 공간 스펙, 거점 큐레이션, 실제 유저 검증 후기 등 '사실 기반 데이터' 블록입니다. 해당 영역은 데이터 통제의 기준점인 대조군(Control Group)으로 변형 없이 고정하여, 최상단 가변 블록의 메시지 변주에 따른 순수 CVR(전환율) 기여도만을 격리 추적할 수 있도록 설계되었습니다.
