# 📡 서버 간 데이터 연동(CAPI)을 통한 웹-앱 광고 기여도 복원 프로젝트

본 프로젝트는 서비스 특성상 웹과 앱으로 파편화된 유저의 행동 데이터를 유기적으로 연결하고, 이를 주요 광고 매체(Meta, Google, Kakao) 서버로 직접 전송하여 **광고 최적화 효율을 극대화한 데이터 파이프라인 구축 프로젝트**입니다.

웹 광고 유입 데이터와 앱 내 결제 데이터 간의 끊어진 연결고리를 **GTM(웹) - Firebase(앱) - AWS DB(구매)의 핵심 식별자 매핑을 통해 역추적 모델로 복원**해냈으며, 그 결과 Meta 광고 관리자 기준 **구매 이벤트 매칭 품질(EMQ) 점수를 기존 5.6점에서 현재 8.1점(우수)까지 상향**시켰습니다.

---

## 💡 기획 배경

1. **서비스의 특성 (웹 랜딩의 필수성)**
   - 파이브스팟은 일반 커머스와 달리 유저에게 서비스의 가치를 설명하고 설득하는 과정이 반드시 필요한 고관여 서비스입니다. 따라서 인지도가 낮은 상태에서 앱으로 바로 랜딩 시 구매 유도가 어려워, **100% 웹(Web) 페이지로 광고 트래픽을 랜딩**시키고 있습니다.
2. **웹-앱 간의 데이터 단절 보틀넥**
   - 하지만 **실제 최종 구매의 절반 이상은 앱(App) 내에서 발생**하고 있었습니다. 딥링크 기술이 없는 상태였기 때문에, 웹에서 광고를 보고 들어온 유저가 앱을 다운로드 받아 결제했을 때 "어떤 광고를 보고 들어와서 샀는지" 매체 데이터가 완전히 끊기는 추적 누수 리스크가 있었습니다.
3. **해결책: 식별자 매핑을 통한 데이터 연동**
   - 이 문제를 해결하기 위해 각 환경의 핵심 식별자를 유기적으로 연결했습니다. **웹(GTM 수집 `user_id`/`user_pseudo_id`) ➡️ 앱 로그인(Firebase SDK `user_id` 이벤트 발생) ➡️ 결제 데이터(AWS DB `client_uid`)**를 상호 매핑하여, 앱에서 결제한 유저가 과거 웹 단계에서 어떤 광고를 보고 들어왔었는지 완벽하게 역추적하여 매체 서버(S2S)로 안전하게 쏘아주는 파이프라인을 구축했습니다.

## 🏗️ 시스템 아키텍처 및 데이터 흐름

![S2S Pipeline Architecture](./s2s.png)

```text
[1단계: 웹 행동 수신 (GTM)]
 └─ 유저가 웹 랜딩페이지 진입 시, GTM을 통해 맞춤 변수(fbp, user_agent, user_ip) 및
    유저 식별자(user_id, user_pseudo_id)를 추출하여 GCP 빅쿼리(BigQuery)에 적재.
               │
               ▼
[2단계: 앱 로그인 연동 (Firebase SDK)]
 └─ 웹을 탐색하던 유저가 앱을 다운로드한 후 로그인하는 시점에
    Firebase SDK를 통해 'user_id' 이벤트를 발생시켜 웹과 앱 데이터의 연결고리 확보.
               │
               ▼
[3단계: 결제 발생 및 데이터 결합 (AWS DB ➡️ order-data-fetcher)]
 └─ 토스 결제 완료 웹훅 발생 시, AWS 데이터베이스에서 'client_uid' 기반의 구매 원장 데이터 로드.
 └─ 핵심 엔진(order-data-fetcher)이 user_id와 client_uid를 매핑 키로 활용하여
    빅쿼리의 UNNEST 문법으로 과거 웹 로그 데이터를 실시간 결합(조인) 및 SHA256 암호화.
               │
               ▼
[4단계: 다중 매체 전송] ───► [웹-앱 데이터 연결 & Meta CAPI 점수 8.1점 달성 🎉]
```

## 🚀 프로젝트 주요 과제 및 성과

### 1. Meta 구매 이벤트 매칭 품질 (EMQ) 8.1점 달성
* 파편화되어 유실되던 웹-앱 간 유저 식별 파라미터 매핑 기법을 고도화하여, Meta 이벤트 관리자 기준 **구매(Purchase) 이벤트의 매칭 품질 점수를 기존 5.6점에서 8.1점(우수)까지 상향**시켰습니다.
* 끊겨있던 대량의 앱 결제 모수가 광고 매체 서버로 정상 복원됨에 따라, 매체 머신러닝이 진성 결제 유저 세그먼트를 더 정교하게 학습할 수 있는 데이터 기반을 마련했습니다.

### 2. GTM·빅쿼리 UNNEST 활용 고정밀 매칭 파라미터 확보
* 일반적인 자동 수집 방식으로는 유실되기 쉬운 브라우저 정보 및 매체 식별자를 확보하기 위해, **GTM(구글 태그 매니저)을 활용해 유저 행동 데이터(`fbp`, `user_agent`, `user_ip`)를 직접 맞춤 변수로 선언하여 빅쿼리에 수집**했습니다.
* 이후 핵심 엔진에서 빅쿼리의 `UNNEST(event_params)` 문법을 통해 중첩된 이벤트 구조를 정밀하게 추출 및 매핑함으로써, S2S 발송 시점에 업계 최고 수준의 데이터 정합성을 확보했습니다.

### 3. 새로운 매체 추가가 유연한 구조 설계
* 메시지 큐 기반의 독립 발송 구조를 채택하여, 향후 틱톡이나 트위터 등 **새로운 광고 매체가 추가되더라도 기존의 결제 수신 및 데이터 결합 코드를 전혀 건드리지 않고**, 새 매체의 전송 코드만 독립적으로 추가 배포하면 되는 뛰어난 확장성을 확보했습니다.
