# 📡 서버 간 데이터 연동(CAPI)을 통한 웹-앱 광고 기여도 복원 프로젝트

본 프로젝트는 서비스 특성상 웹과 앱으로 파편화된 유저의 행동 데이터를 유기적으로 연결하고, 이를 주요 광고 매체(Meta, Google, Kakao) 서버로 직접 전송하여 **광고 최적화 효율을 극대화한 데이터 파이프라인 구축 프로젝트**입니다.

웹 광고 유입 데이터와 앱 내 결제 데이터 간의 끊어진 연결고리를 **Firebase SDK 식별자(`user_id`)와 내부 데이터베이스(DB) 결합을 통해 역추적 모델로 복원**해냈으며, 그 결과 Meta 광고 관리자 기준 **구매 이벤트 매칭 품질(EMQ) 점수를 기존 5.6점에서 현재 8.1점(우수)까지 상향**시켰습니다.

---

## 💡 기획 배경 (왜 만들었는가?)

1. **서비스의 특성 (웹 랜딩의 필수성)**
   - 파이브스팟은 일반 커머스와 달리 유저에게 서비스의 가치를 설명하고 설득하는 과정이 반드시 필요한 고관여 서비스입니다. 따라서 인지도가 낮은 상태에서 앱으로 바로 랜딩 시 구매 유도가 어려워, **100% 웹(Web) 페이지로 광고 트래픽을 랜딩**시키고 있습니다.
2. **웹-앱 간의 데이터 단절 보틀넥**
   - 하지만 **실제 최종 구매의 절반 이상은 앱(App) 내에서 발생**하고 있었습니다. 딥링크 기술이 적용되지 않은 상태였기 때문에, 웹에서 광고를 보고 들어온 유저가 앱에서 결제했을 때 "어떤 광고를 보고 들어와서 샀는지" 매체 데이터가 완전히 끊기는 추적 누수 리스크가 있었습니다.
3. **해결책: 식별자 매핑을 통한 행동 역추적**
   - 이 문제를 해결하기 위해 **웹 행동 시점에 Firebase SDK로 생성한 유저 식별값(`user_id`/`user_pseudo_id`)과 백엔드 데이터베이스(AWS RDS)의 실제 구매 원장 데이터를 정밀하게 결합**했습니다. 이를 통해 앱 결제 유저의 과거 웹 탐색 행동을 역추적하여 매체 서버(S2S)로 안전하게 쏘아주는 파이프라인을 구축했습니다.

## 🏗️ 시스템 데이터 흐름

```text
[웹 광고 클릭 및 서비스 진입] ──► Firebase SDK가 웹 유저 식별값(user_id) 채록
                                                    │
[유저가 앱(App) 다운로드 후 결제 완료] ◄──────────────┘
               │
 [Toss 결제 완료 웹훅 발생 ➡️ GCP Pub/Sub 큐 안전 적재]
               │
               ▼
 [★ 핵심 데이터 결합 엔진 가동 (order-data-fetcher)]
  - AWS RDS: 유저 결제 데이터 조인
  - GCP BigQuery: Firebase user_id 기반의 과거 웹 탐색 행동(fbp, user_ip, UA 등) 역추적 결합
  - 개인정보 보안 암호화: 이메일, 전화번호 데이터를 Meta 규격에 맞춰 SHA256 해싱
               │
               ▼
 [다중 광고 매체 전송 체계 가동] ───► [웹-앱 데이터 연결 & Meta CAPI 점수 8.1점 달성 🎉]
```

## 🚀 프로젝트 주요 과제 및 성과

### 1. Meta 구매 이벤트 매칭 품질 (EMQ) 8.1점 달성
* 파편화되어 유실되던 웹-앱 간 유저 식별 파라미터 매핑 기법을 고도화하여, Meta 이벤트 관리자 기준 **구매(Purchase) 이벤트의 매칭 품질 점수를 기존 5.6점에서 8.1점(우수)까지 상향**시켰습니다.
* 끊겨있던 대량의 앱 결제 모수가 광고 매체 서버로 정상 복원됨에 따라, 매체 머신러닝이 진성 결제 유저 세그먼트를 더 정교하게 학습할 수 있는 데이터 기반을 마련했습니다.

### 2. GTM·Firebase 기반 고정밀 매칭 파라미터 확보
* 일반적인 자동 수집 방식으로는 유실되기 쉬운 브라우저 정보 및 매체 식별자를 확보하기 위해, **GTM(구글 태그 매니저) 및 Firebase SDK를 활용해 유저 행동 데이터(`fbp`, `user_agent`, `user_ip`)를 맞춤 변수로 직접 동기화하여 수집**했습니다.
* 이후 빅쿼리(BigQuery)에서 `UNNEST(event_params)` 문법을 통해 중첩된 이벤트 파라미터 구조를 정밀하게 해제 및 추출하여 결제 데이터와 매핑함으로써, S2S 발송 시점에 업계 최고 수준의 데이터 정합성을 확보했습니다.

### 3. 새로운 매체 추가가 유연한 구조 설계
* 메시지 큐 기반의 독립 발송 구조를 채택하여, 향후 틱톡이나 트위터 등 **새로운 광고 매체가 추가되더라도 기존의 결제 수신 및 데이터 결합 코드를 전혀 건드리지 않고**, 새 매체의 전송 코드만 독립적으로 추가 배포하면 되는 뛰어난 확장성을 확보했습니다.

### 4. 멀티 클라우드 데이터 실시간 결합 (`order-data-fetcher`)
* 실시간 결제 알림으로 들어오는 파편화된 데이터에 AWS의 구매 원장 데이터와 GCP의 행동 로그(광고 기여 식별값) 데이터를 밀리초(ms) 단위로 실시간 조인하여 마케팅 데이터 마트의 비즈니스 가치를 극대화했습니다.
* 민감할 수 있는 유저 정보는 매체별 컴플라이언스 기준에 일치하도록 정규표현식(Regex) 정제 후 `SHA256` 단방향 해싱 처리를 수행하여 정합성과 보안성을 동시에 확보했습니다.
